# 分阶段实施路线

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 17. 分阶段实施路线

### 阶段零：技术验证（1–2 天，先做再开发）

在写业务代码前，用一个最小骨架验证以下 6 项；任何一项不通过，先调整方案再进入阶段一：

1. Astro SSR 文章页：5,000 中文字、10 个标签、10 张图片，测量 Worker CPU p50/p95；目标 p95 < 8 ms（免费版上限 10 ms）。
2. Rust API + D1：1,000 篇文章、标签关联、分页查询；确认 50 次查询/请求和 100 KB 语句限制内。
3. R2 + 图片代理：5 MB 图片上传、content_hash 去重、长期缓存头正确；确认 workers.dev 下不依赖传统 Cache API，图片重复访问由浏览器缓存承担；若后续绑定自定义域，可再验证传统 Cache API；Workers Cache 不依赖自定义域，另见第 6 项。
4. Access：workers.dev path-based 保护 `/admin` 与 `/api/admin`，验证登录跳转、API 401/302 处理，以及 Static Assets 下 `ctx.access` 不可用的替代校验。
5. 备份：`wrangler d1 export` 导入空库、R2 文件恢复、文章/图片引用校验。
6. Workers Cache（CPU 接近上限时必做）：在 preview 开启 `cache.enabled`，验证公开文章页 HIT/MISS、`Cache-Tag` purge、管理页/API 为 `no-store`、静态资源与 Service Binding 的计费变化；冷缓存 SSR 仍须低于 10 ms，缓存不能挽救首次请求超限。

**Go/No-Go：**CPU p95 稳定低于 8 ms 且 Access/备份闭环通过，进入阶段一；CPU 接近 10 ms 但冷缓存仍低于上限，先评估 Workers Cache；冷缓存已超过 10 ms 或缓存计费不可接受，改用“公开页构建时预渲染 + 发布后触发重建”，或接受 Workers Paid（\$5/月，超出 50 元/年预算）。

### 阶段一：最小可用博客

- 初始化 Monorepo、Astro 和 Rust Worker。
- 建立 D1 migration 和 R2 绑定。
- 完成首页、文章列表和文章详情。
- 完成后台新建、编辑、发布和归档。
- 完成图片上传与 Markdown 插入。
- 使用 workers.dev 公开访问。

验收标准：能够从后台发布一篇带图片的文章，并在公开地址正常阅读。

### 阶段二：完整博客体验

- 标签、归档、关于页和搜索框。
- RSS、sitemap 和 SEO 元信息。
- 深色模式、响应式布局和可访问性检查。
- 缓存失效和后台设置。
- 备份、恢复和监控用量。

验收标准：常用博客功能完整，发布和恢复流程经过验证。

### 阶段三：增强功能

- 文章历史版本。
- 更好的 Markdown 编辑器。
- 图片压缩和缩略图。
- 评论系统与垃圾评论防护。
- 自定义域名。
- 根据实际容量迁移到 PostgreSQL。
