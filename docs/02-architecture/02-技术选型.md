# 技术选型

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 4. 技术选型

### 4.1 前端

| 技术 | 用途 |
|-|-|
| Astro | 页面结构、SSR、静态资源和 SEO |
| TypeScript | 前端类型约束和 API 类型定义 |
| Astro 组件 | 博客页面和后台界面 |
| 少量原生 JavaScript | 菜单、图片上传、编辑器等交互 |
| CSS 变量 | 明暗主题、颜色和响应式设计 |

第一版不引入大型前端 UI 框架。后台编辑器先使用“Markdown 文本框 + 预览”，稳定后再考虑 CodeMirror 等编辑器组件。

**版本与图片处理：**当前本地实现固定 Astro 7.4 + `@astrojs/cloudflare` 14.4；显式设置 `imageService: 'passthrough'`，不要用 Astro `<Image>` 处理 R2 图片，避免默认 Cloudflare Images binding 消耗 5,000 次/月免费转换额度后返回 9422 错误。Markdown 在发布时由 Rust 渲染为 HTML 并存储，公开页不在请求路径解析 Markdown 或做语法高亮。

### 4.2 后端

| 技术 | 用途 |
|-|-|
| Rust stable | 后端主要语言 |
| workers-rs | Workers 请求、响应和平台绑定 |
| wasm-bindgen | Rust 与 JavaScript 运行时互操作 |
| Serde | 请求和响应数据结构序列化 |
| D1 prepared statements | 参数化 SQL 查询 |
| Repository 模式 | 隔离业务逻辑和数据库实现 |

第一版不强行引入复杂 ORM。D1 使用参数化 SQL，并将查询集中在 repository 模块中，以减少 Wasm 体积并方便以后迁移 PostgreSQL。

**本地实现：**当前 MVP 使用 `axum + tokio + rusqlite` 跑在普通 Rust 进程中，以 SQLite 和本地目录模拟 D1/R2。HTTP 契约、service 规则和 repository 边界与生产方案一致，迁移到 Workers 时主要替换 repository / storage 实现和运行时入口。

**Markdown 渲染与事务：**Rust 侧用 `pulldown-cmark`（关闭原始 HTML）在发布时生成 `content_html`；发布请求同样受 10 ms CPU 限制，5,000 字级文章可接受，超长文章需在浏览器端预渲染或拆分处理。后台预览调用同一个服务端渲染接口，避免预览与公开页不一致。D1 多语句写入使用 `batch()`，保证文章与标签关联原子提交；不要依赖交互式事务。若 Markdown 与 HTML 合计接近 D1 单条 SQL 100 KB 上限，建议把 `content_html` 放独立表或 R2，分两条语句写入。

### 4.3 数据与存储

| 数据类型 | 存储位置 | 示例 |
|-|-|-|
| 文章元数据 | D1 | 标题、摘要、slug、状态、发布时间 |
| 文章正文 | D1 | Markdown 文本 |
| 标签与关联关系 | D1 | 标签、文章标签关系 |
| 图片元数据 | D1 | R2 key、MIME、大小、宽高 |
| 图片和附件 | R2 | WebP、JPEG、PNG 等文件 |
| 网站设置 | D1 | 网站名称、简介、社交链接 |
