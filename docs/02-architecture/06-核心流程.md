# 核心流程

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 8. 核心流程

### 8.1 发布文章

1. 管理员打开后台编辑器。
2. 填写标题、slug、摘要、正文、标签和封面。
3. 前端进行必填项和 slug 格式校验。
4. Rust API 再次校验数据，不依赖前端校验。
5. 使用 D1 batch() 保存文章和标签关联，保证原子提交；同时生成 content_html 和新的内容版本号。
6. 将状态设为 `published`，写入 `published_at`。
7. 第一版不做整页边缘缓存，发布后无需清理；若后续启用缓存，优先评估 Workers Cache + Cache-Tag purge，并用版本化 key 兜底。
8. 新文章 URL 首次访问即命中最新数据；列表页在无整页缓存时同样立即可见。

### 8.2 上传图片

1. 管理员在编辑器选择图片。
2. 前端检查大小；扩展名不可信，最终以文件头识别结果为准。
3. Rust API 检查真实文件内容、MIME 类型和大小。
4. 计算文件内容哈希：先查 content_hash，命中则复用；未命中才生成不可预测的 R2 key。
5. 文件写入 R2，元数据写入 D1。
6. 返回图片 URL，编辑器插入 Markdown 图片语法。
7. 删除图片前检查正文、封面和设置引用；未引用图片保留 30 天后再清理，避免误删。

建议 R2 key：

```Plaintext
posts/2026/10/<content-hash>.<ext>  # ext 由文件头识别，不强制 webp
```

使用内容哈希命名后，可将图片响应设为长期 immutable 缓存；相同内容重复上传时先查 content_hash 并复用，不重复写 R2。

### 8.3 阅读文章

1. 访客请求 Astro 文章页。
2. 第一版不查整页缓存，直接进入渲染；图片和静态资源由浏览器/边缘缓存。
3. 直接通过 Service Binding 调用 Rust API。
4. Rust API 查询 D1 并返回文章数据。
5. Astro 渲染完整 HTML 并返回访客。
6. 若后续启用整页缓存，优先评估 Workers Cache + Cache-Tag；缓存 key 仍应带内容版本号，避免只依赖主动失效。
