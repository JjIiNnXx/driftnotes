# 缓存与性能设计

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 10. 缓存与性能设计

| 内容 | 第一版策略 |
|-|-|
| 静态资源（CSS/JS/字体） | Workers Static Assets，哈希文件名 + 一年 immutable；请求免费且不触发 Worker |
| 图片 | `/images/<hash>.<ext>` 内容寻址；`Cache-Control: public, max-age=31536000, immutable`；API Worker 读取 R2 并返回长期缓存头；workers.dev 下传统 Cache API 不可依赖，第一版由浏览器缓存承担；后续可评估 Workers Cache |
| 首页、文章、标签、归档 HTML | 第一版不做整页边缘缓存，直接 SSR，保证发布立即可见；后续优先评估 Workers Cache（zoneless、支持 Cache-Tag purge），版本化 key + 短 TTL 作为兜底 |
| RSS / sitemap | 动态生成，`Cache-Control: public, max-age=300`；发布后最多 5 分钟更新 |
| 管理页面与 API | `Cache-Control: no-store` |

**关键限制：**`workers.dev` 没有可配置的 zone，无法使用 zone 级 Cache Rules 或 Purge API；官方文档明确自定义域上的传统 Cache API 可用，`workers.dev` 不应依赖它，且它只在单个数据中心生效。Cloudflare 另提供 zoneless 的 Workers Cache（2026 年文档）：在 Wrangler 开启 `cache.enabled` 后按响应头缓存，命中不执行 Worker，支持 `Cache-Tag` 和 `ctx.cache.purge()`；但缓存命中仍按请求计费，启用后静态资源和 Service Binding 请求也计入标准请求，管理页/API 必须显式 `no-store`。第一版仍不启用整页缓存；若阶段零 CPU 接近上限，优先验证 Workers Cache，再考虑预渲染。

性能原则：

- 公开页面由服务端输出完整 HTML，不依赖浏览器请求后才显示文章。
- 列表页只查询摘要所需字段，不读取全部 Markdown 正文。
- 数据库查询建立必要索引，避免全表扫描。
- 图片上传前尽量在本地压缩，正文使用响应式图片和懒加载。
- Rust 依赖按需引入，并开启 release 优化，控制 Wasm 体积。
- 不在免费 Worker 中进行大型图片转码等高 CPU 操作。
- 免费版每次请求 10 ms CPU：Markdown 解析、语法高亮、鉴权和大响应序列化都要前置或裁剪；文章页按 5,000 中文字 + 10 个标签压测。
- 列表页用 batch 或固定 2 条查询取文章和标签，避免 N+1；免费版单次请求最多 50 次 D1 查询。
- 图片经 Worker 代理会消耗请求配额；限制单篇图片数量，优先使用内容哈希缓存和浏览器缓存。
