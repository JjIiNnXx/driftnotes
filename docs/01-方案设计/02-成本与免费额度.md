## 13. 免费额度与成本控制

以下按方案设计时的公开免费额度进行容量规划，实际以 Cloudflare 控制台和最新文档为准：

| 服务 | 主要免费额度 | 本方案控制方式 |
|-|-|-|
| Workers 请求 | 每天 100,000 次动态请求 | 公开页 SSR 与图片代理共用；静态资源请求不计 |
| Workers CPU | 每次请求 10 ms | Markdown 渲染前置；文章页压测；超限改预渲染或升级 Paid |
| Workers 子请求 | 每次请求 50 次 | 列表页用 batch；避免 N+1；Service Binding 调用计入 |
| Static Assets | 请求免费且不限量 | CSS、JS、字体全部走 Assets |
| D1 存储 | 单库 500 MB，账户总计 5 GB | 只存文字和元数据，图片放 R2 |
| D1 查询 | 每天读取 500 万行、写入 10 万行 | 使用索引、分页和缓存 |
| D1 单次限制 | 每次调用 50 条查询；单条 SQL 100 KB；单行 2 MB | 聚合查询；正文限制 80 KB |
| R2 存储 | 10 GB-month 存储 | 上传前压缩，限制单文件 5 MB |
| R2 操作 | 每月 100 万次 Class A、1,000 万次 Class B | 图片长期缓存，限制后台上传 |
| workers.dev | 免费公开地址 | 无 SLA；第一版不购买域名 |

**最紧的约束：**免费版 CPU 10 ms。官方文档明确 SSR、鉴权、解析大载荷常见 10–20 ms；如果阶段零冷缓存压测超过 10 ms，优先评估 Workers Cache（只能消除命中请求的 CPU，不能挽救首次请求），仍超限则把公开页改为构建时预渲染，而不是直接升级付费。Workers Paid 为 \$5/月（约 36 元/月），远超 50 元/年预算。

**账单提醒：**0 元/年不等于无账单。R2、Zero Trust 等产品开通时可能要求绑定支付方式，R2 超额会自动计费；必须在控制台配置用量提醒，并定期检查。

### 成本原则

- 免费额度不是永久承诺，应每季度检查一次用量和规则。
- R2 超额可能产生费用，需要配置用量提醒。
- 后台统计 D1 和 R2 的大致使用量，接近阈值时提前处理。
- 第一版不启用不必要的付费图片转换和高级监控服务。
- 50 元／年预算保留，不为了使用预算而引入额外服务。
- 若启用 Workers Cache：无独立缓存费用，但缓存命中仍按请求计费；启用后静态资源和 Service Binding 请求也按标准请求计费，需重新核算 100,000 次/天。
