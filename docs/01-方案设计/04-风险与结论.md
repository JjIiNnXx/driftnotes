# 风险、迁移预留与结论

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 18. 风险与应对

| 风险 | 影响 | 应对方式 |
|-|-|-|
| Rust Wasm 依赖或工具链不兼容 | 构建失败、调试困难 | 阶段零先验证 D1/R2/Service Binding/FormData；固定 Rust 与 worker-build 版本；纯逻辑用 cargo test，HTTP 用 Miniflare |
| Wasm 体积或启动时间超限 | 部署失败或冷启动慢 | 减少依赖、release 优化、wasm-opt；Worker 未压缩上限 64 MiB、启动 1 秒，通常不是首要瓶颈 |
| 免费版 CPU 10 ms | SSR 返回 1102，页面不可用 | Markdown 渲染前置、关闭运行时语法高亮、压测 p95；冷缓存超限先评估 Workers Cache，仍超限改公开页预渲染，或接受 Paid |
| D1 容量与单次限制 | 长文写入失败、查询变慢 | 单库 500 MB；正文 ≤80 KB；单次 50 条查询；用 batch、索引和分页 |
| R2 超额产生费用 | 意外账单 | 上传限制、内容哈希去重、缓存、用量提醒和定期清理 |
| workers.dev 无 zone 级缓存 | 无法使用 zone 级 Purge | 第一版不做整页缓存；图片内容哈希 + 浏览器缓存；后续评估 Workers Cache（支持 Cache-Tag purge，但改变计费范围）或版本化 key |
| 缓存导致文章不更新 | 前后台内容不一致 | 统一缓存 key 和版本号；发布后不依赖“清理所有缓存” |
| Access 与 Static Assets 身份校验 | 管理接口被绕过或误拦截 | Access path-based 保护；校验 JWT 或内部 HMAC；处理 302/HTML 登录跳转 |
| Markdown 存储型 XSS | 后台或访客被注入脚本 | 禁用原始 HTML、过滤危险链接、发布时净化、CSP |
| FTS5 与备份冲突 | d1 export 失败，备份不可用 | 备份前删除虚拟表或只导出业务表；恢复后重建索引；或第一版先用 LIKE |
| 图片代理消耗请求配额 | 100,000 次/天被图片耗尽 | 限制单篇图片数、内容哈希缓存、浏览器缓存；必要时绑定域名走 R2 自定义域 |
| 后台被攻击 | 数据被修改或删除 | Access、权限校验、限流、审计日志和备份 |
| 单厂商故障或中国大陆访问不稳定 | 网站或后台暂时不可用 | 保留代码和独立数据备份；若大陆访问是硬要求，重新评估托管方案 |
| workers.dev 地址不可用或变更 | 访问入口变化 | 后续可绑定自有域名，内容路径保持稳定 |

## 20. 最终结论

**评审结论：总体可行，但需先完成阶段零技术验证，不能直接按“0 元/年 + 全 SSR + zone 级主动缓存失效”进入开发。**

可行的部分：Astro 7.4 + `@astrojs/cloudflare` 14.4 部署到 Workers；Rust 通过 workers-rs 使用 D1、R2、Service Binding；Access 可对 workers.dev 的 `/admin` 与 `/api/admin` 做 path-based 保护；D1 500 MB/5 GB、R2 10 GB-month 对个人博客足够；静态资源请求免费。

**必须先验证或修正的部分：**

- **CPU：**免费版 10 ms/请求，官方文档称 SSR、鉴权、大载荷解析常见 10–20 ms；必须把 Markdown 渲染前置到发布时，压测文章页；冷缓存超限先评估 Workers Cache，仍超限改公开页预渲染或升级 Paid。
- 缓存：workers.dev 没有 zone 级 Cache Rules/Purge；传统 Cache API 在 workers.dev 不可依赖，第一版不做整页边缘缓存，图片用内容哈希 + 浏览器缓存。Workers Cache 是 zoneless 且支持 Cache-Tag purge，但启用后静态资源/Service Binding 也按请求计费，作为 CPU 不达标时的优先验证项，而非 v1 前提。
- **认证：**Access 可用，但 Static Assets 下 `ctx.access` 不传给用户 Worker；需校验 Access JWT 或使用内部 HMAC，并处理登录过期时的 302/HTML。
- **数据与备份：**D1 单条 SQL 100 KB、50 查询/请求；文章正文限制 80 KB；若用 FTS5，备份需先处理虚拟表。
- **内容安全：**Markdown 禁用原始 HTML、过滤危险链接、发布时净化；上传校验文件头/尺寸，防止伪造 MIME。

**建议：**先做 1–2 天的阶段零骨架，按第 17 章的 Go/No-Go 标准决策；通过后再进入阶段一。若 CPU 不达标且不接受 \$5/月，先验证 Workers Cache（冷缓存仍需低于 10 ms），再采用“公开页构建时预渲染 + 发布后触发重建”的 Plan B；两者都可保持在免费额度内，但需监控请求计费。
