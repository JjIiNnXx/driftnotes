# 后续迁移 PostgreSQL 的预留

## 19. 后续迁移 PostgreSQL 的预留

虽然第一版使用 D1，但仍为 PostgreSQL 保留迁移空间：

- 业务 handler 不直接拼接 SQL。
- 所有数据库操作集中在 repository 模块。
- 尽量使用通用 SQL 和标准数据类型。
- 不依赖 SQLite 专属函数实现核心业务。
- 使用 migration 文件记录所有表结构变化。
- API 响应结构不暴露 D1 特有字段。
- 迁移时先双写或离线导出导入，再切换 repository 实现。

这样，未来如果单库接近付费版 10 GB 上限，或需要更强并发和查询能力，可以迁移到托管 PostgreSQL，而不重写前端和大部分业务逻辑。
