### 架构说明

采用两个 Worker，但只向用户暴露一个公开入口：

1. **Web Worker** 负责 Astro 页面渲染、静态资源和同源 API 转发。
2. **Rust API Worker** 负责业务逻辑、权限校验、D1 和 R2 操作。
3. 两个 Worker 通过 **Service Binding** 通信，避免跨域和公网 API 配置。
4. Rust API Worker 不启用公开 workers.dev 地址，减少攻击面。
5. 静态资源和图片使用长期缓存，管理接口禁止缓存；HTML 第一版不缓存（后续可评估 Workers Cache）。

该结构比单 Worker 稍复杂，但前后端职责清晰，适合长期维护和 Rust 技术实践。

**补充约束：**免费版 Workers 每次请求只有 10 ms CPU；Service Binding 不额外计费，但每次调用计入子请求配额（免费版 50 次/请求）。静态资源请求免费且不会触发 Worker。管理请求经 Web Worker 转发时，应附加内部 HMAC 头，Rust API 只接受带该头的请求，不能仅依赖“API Worker 没有公开地址”。
