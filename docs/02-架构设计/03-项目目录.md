# 项目目录设计

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28），已按当前本地实现更新

## 5. 项目目录设计

当前仓库是轻量 Monorepo，但不再拆成 `apps/web` + `apps/api` 的 Cloudflare 双 Worker 目录，而是把可运行的本地前后端直接放在根目录：

```text
driftnotes/
├── frontend/                        # Astro 7 SSR 前端
│   ├── src/
│   │   ├── components/              # 卡片、编辑器、空状态等组件
│   │   ├── layouts/                 # BaseLayout / AdminLayout
│   │   ├── pages/
│   │   │   ├── index.astro          # 首页
│   │   │   ├── posts/               # 文章列表与详情
│   │   │   ├── tags/                # 标签列表与标签文章
│   │   │   ├── archive.astro        # 归档
│   │   │   ├── about.astro          # 关于
│   │   │   ├── admin/               # 管理后台
│   │   │   ├── rss.xml.ts           # RSS
│   │   │   └── sitemap.xml.ts       # Sitemap
│   │   ├── lib/                     # API Client、格式化函数
│   │   └── styles/                  # 公开站与后台样式
│   ├── plugins/                     # 本地请求日志 Vite 插件
│   ├── public/covers/               # 内置封面 SVG
│   ├── astro.config.mjs
│   └── package.json
│
├── backend/                         # Rust + Axum API
│   ├── src/
│   │   ├── main.rs                  # 入口、AppState、日志初始化
│   │   ├── router.rs                # 路由、CORS、请求日志中间件
│   │   ├── handlers/                # 公开 / 管理 / 图片 HTTP 层
│   │   ├── services/                # 业务规则、Markdown、上传
│   │   ├── repositories/            # SQLite 查询与事务
│   │   ├── storage/                 # 本地对象存储抽象
│   │   ├── db/                      # 建表与示例数据
│   │   ├── models.rs                # 请求 / 响应模型
│   │   └── logging.rs               # 按天日志与清理任务
│   ├── data/                        # 运行时生成：SQLite + 上传文件
│   └── Cargo.toml
│
├── docs/                            # 文档集
│   ├── index.toml                   # 文档集总索引
│   ├── 01-方案设计/
│   ├── 02-架构设计/
│   ├── 03-开发规范/
│   ├── 04-运维部署/
│   └── 05-评审记录/
│
├── log/                             # 运行时日志（前后端分开）
│   ├── backend/                     # backend/YYYY-MM-DD.log
│   └── frontend/                    # frontend/YYYY-MM-DD.log
│
├── .github/workflows/               # CI：ci.yml，PR 上的密钥扫描与质量门禁
├── .githooks/pre-push               # 本地阻止直推 main
│
├── script/
│   ├── dev.sh                       # 一键启动前后端
│   ├── check.sh                     # 格式、测试、构建检查
│   └── setup-git-hooks.sh           # 启用 .githooks
│
├── package.json                     # 根脚本与前端 workspace
└── README.md
```

**契约同步：**当前本地 MVP 的 TypeScript 类型和请求封装集中在 `frontend/src/lib/api.ts`，Rust 响应结构在 `backend/src/models.rs` 与各 service 中定义。进入生产阶段后，建议用 `ts-rs` 从 Rust 模型生成 TypeScript 类型，或维护 OpenAPI 并生成客户端；否则前后端字段会逐渐漂移，Rust 的类型安全优势会被手写接口抵消。

**目录边界：**`backend/data/` 与 `log/` 都是运行时产物，不提交到版本库；`docs/` 只放稳定文档，每日日志不进入文档集。
