## 14. 本地开发与部署

### 14.1 本地环境

当前本地 MVP 不依赖 Cloudflare 账号或任何付费服务，只需要：

- Rust 1.85+（`cargo` 在 PATH 中）
- Node.js 22.23+ 与 npm
- 两个本地端口：Rust API `8787`、Astro `4321`

本地运行形态：

| 组件 | 本地实现 | 生产目标 |
|-|-|-|
| 前端 | Astro 7.4 + `@astrojs/cloudflare` 14.4，SSR | Astro + Cloudflare Workers |
| 后端 | Rust + Axum，独立进程 | Rust → WebAssembly Worker |
| 数据库 | SQLite（`rusqlite`，bundled） | Cloudflare D1 |
| 图片 | `backend/data/storage/` | Cloudflare R2 |
| 日志 | `log/backend`、`log/frontend` 按天文件 | Workers Logs / 外部日志服务 |
| 认证 | 无（仅本机） | Cloudflare Access + 服务端校验 |

### 14.2 一键启动

```bash
npm install
bash script/dev.sh
```

`script/dev.sh` 会：

1. 检查 `cargo` / `npm`，必要时安装前端依赖；
2. 启动 Rust API，等待 `/api/health` 返回 200；
3. 启动 Astro dev server，等待首页可访问；
4. 输出博客、后台、API 和日志路径；
5. 按 `Ctrl+C` 时同时停止前后端。

首次启动需要编译 Rust 依赖，可能需要几分钟。启动后访问：

| 地址 | 说明 |
|-|-|
| `http://127.0.0.1:4321` | 公开博客 |
| `http://127.0.0.1:4321/admin` | 管理后台 |
| `http://127.0.0.1:8787/api/health` | Rust API 健康检查 |

数据目录默认 `backend/data/`，日志目录默认 `log/`。停止服务后删除 `backend/data/` 可恢复示例内容；删除 `log/` 下的日期文件不会影响业务数据。

### 14.3 环境划分

至少区分：

| 环境 | 用途 | 数据要求 |
|-|-|-|
| local | 本机开发 | SQLite + 本地文件，示例数据 |
| preview | 部署前验证 | 独立预览 D1、R2，避免污染生产 |
| production | 正式博客 | 独立生产资源和密钥 |

### 14.4 生产部署顺序

1. 创建开发、预览和生产 D1 数据库。
2. 创建对应 R2 Bucket。
3. 执行数据库 migration。
4. 配置 Rust API Worker 绑定和 Secrets。
5. 部署 Rust API Worker，不开放公网地址。
6. 配置 Web Worker 到 API Worker 的 Service Binding。
7. 部署 Astro Web Worker。
8. 启用唯一公开 workers.dev 地址。
9. 配置 Access，保护 `/admin/*` 与 `/api/admin/*`。
10. 验证文章发布、图片上传、缓存、RSS、日志和备份流程。

### 14.5 日志

本地日志按天写入前后端各自目录，保留 3 天，每 72 小时清理一次。详细格式、查看方式和生产替代方案见 [日志规范](../03-development/04-日志规范.md)。
