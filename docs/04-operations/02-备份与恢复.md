# 备份与恢复

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28）

## 16. 备份与恢复

免费托管不等于完整备份，必须保留独立副本。

**两个容易忽略的点：**D1 Time Travel 免费版保留 7 天，可作为误删恢复，但不能替代独立备份。若阶段二使用 FTS5 虚拟表，`wrangler d1 export` 会因虚拟表失败；备份前需删除 FTS 表或只导出业务表，恢复后重建索引并重新灌入。

### 16.1 备份内容

- GitHub 中的前端、后端和 migration 代码。
- 定期导出的 D1 SQL 数据。
- R2 中的重要原图和附件。
- 不含密钥的配置清单和资源名称清单。

### 16.2 建议频率

- 每次发布重要文章后导出一次 D1。
- 每周至少保留一次完整逻辑备份。
- 本地或另一个可信存储位置保留最近 4 周备份。
- 每季度进行一次恢复演练，而不只是确认备份文件存在。

### 16.3 本地备份

本地 MVP 的备份对象是 SQLite 数据库与图片目录：

```bash
mkdir -p backup
sqlite3 backend/data/blog.db ".backup 'backup/blog-$(date +%F).db'"
cp -a backend/data/storage "backup/storage-$(date +%F)"
```

建议在停止写入或停止服务后执行，恢复时把数据库和 `storage/` 一起放回 `backend/data/`。SQLite 的 WAL 文件不需要单独复制，`.backup` 会生成一致快照。

### 16.4 恢复顺序

1. 恢复代码和配置。
2. 创建空 D1 并执行 migration。
3. 导入数据备份。
4. 恢复 R2 文件。
5. 校验文章、图片和设置引用。
6. 再开放公开访问。
