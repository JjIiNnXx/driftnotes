# 日志规范

> 文档集索引：[index.toml](../index.toml) · 当前本地 MVP 的日志实现

## 目录与文件

前后端日志完全分开，统一放在仓库根目录的 `log/`：

```text
log/
├── backend/
│   └── 2026-10-28.log
└── frontend/
    └── 2026-10-28.log
```

- 文件名使用本地日期 `YYYY-MM-DD.log`，每天一个文件。
- 后端由 `backend/src/logging.rs` 写入；前端由 `frontend/plugins/request-logger.mjs` 写入。
- `log/**/*.log` 不进入版本库；目录由 `script/dev.sh` 启动时自动创建。

## 保留与清理

| 项目 | 规则 |
|-|-|
| 保留窗口 | 今天 + 前两天，共 3 天 |
| 清理频率 | 启动时清理一次，之后每 72 小时清理一次 |
| 清理范围 | 仅删除文件名符合 `YYYY-MM-DD.log` 的日期日志 |
| 失败策略 | 清理失败不影响服务启动；日志写入失败最多退化为 stderr |

后端清理任务随 Tokio runtime 启动；前端清理任务挂在 Vite dev server 上，`unref()` 后不会阻止进程退出。跨天时自动写入新文件，不需要重启。

## 格式

统一行格式：

```text
2026-10-28T23:59:12.345+08:00 [INFO] http: GET /api/posts -> 200 4ms size=- ip=127.0.0.1 ua="curl/8.8.0"
```

字段：

| 字段 | 说明 |
|-|-|
| 时间 | 本地时间，精确到毫秒，带时区偏移 |
| 级别 | `INFO` / `WARN` / `ERROR` |
| target | `app`、`db`、`http`、`post`、`asset`、`internal` 等 |
| 前端范围 | SSR 页面、`/api`、`/images`、RSS/Sitemap；跳过 Vite 内部模块与静态资源 |
| 消息 | 方法、路径、状态码、耗时、请求体大小、客户端地址、User-Agent |

记录规则：

- 2xx / 3xx：`INFO`
- 4xx：`WARN`
- 5xx 与内部错误：`ERROR`
- 请求中止：`WARN`，记录 `aborted`
- 服务级动作：文章创建 / 更新 / 归档、图片上传 / 复用 / 删除
- 不记录请求体、Markdown 正文、Cookie、Authorization、密码或密钥
- 环境变量 `BLOG_LOG_DIR` 覆盖后端日志根目录；`FRONTEND_LOG_DIR` 覆盖前端日志目录

## 查看方式

```bash
# 今天的后端请求
tail -f log/backend/$(date +%F).log

# 今天的前端 SSR / API 请求
tail -f log/frontend/$(date +%F).log

# 查找错误
rg '\[ERROR\]' log/backend log/frontend

# 查看慢请求（前端日志单位为 ms）
rg ' [0-9]{3,}\.[0-9]ms ' log/frontend/$(date +%F).log
```

`script/dev.sh` 不再额外保存控制台日志：Rust 的编译与启动输出直接打印在当前终端；Astro dev server 的诊断日志由它自己维护，可用 `cd frontend && npx astro dev logs` 查看。业务请求日志以 `log/` 下的日期文件为准。

## 生产阶段

本地文件日志只用于开发。迁移到 Cloudflare Workers 后，文件系统不可写，应改用：

- Workers Logs / Tail Workers 收集请求与异常；
- Cloudflare Access 审计日志记录后台登录；
- 外部日志服务做长期检索与告警；
- 结构化 JSON 字段，至少保留 request id、路径、状态码、耗时、Worker 版本和部署环境。

生产日志不得记录正文、用户 Cookie 或 Access JWT。
