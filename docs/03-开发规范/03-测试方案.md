# 测试方案

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28），已按当前本地实现更新

## 15. 测试方案

### 15.1 当前自动化检查

本地唯一质量门禁是：

```bash
bash script/check.sh
# 或 npm run check
```

执行顺序：

1. 校验 `docs/index.toml` 可解析，且索引中的文档路径都存在；
2. `cargo fmt --check`；
3. `cargo test`；
4. `npm --workspace frontend run build`。

当前 Rust 单元测试覆盖纯逻辑：

- 图片 Magic Bytes 识别；
- Markdown 代码块渲染；
- 原始 HTML 与危险链接净化；
- 日志日期解析与 3 天保留边界。

本地没有前端单元测试或类型检查；`astro build` 是前端的主要构建门禁，CI 运行同一套检查。

### 15.2 CI

`.github/workflows/check.yml` 在 pull request 和 push 到 `main` 时运行，执行 `npm ci` 后调用 `bash script/check.sh`，与本地质量门禁一致。

`.github/workflows/guard-main.yml` 在 `main` 收到推送后做兜底检查：

- `github.event.forced` 为真时失败，提示不要 force push；
- 通过 GitHub API 检查提交是否关联 PR，未关联则失败并提示使用 feature 分支。

私有仓库免费计划不支持 GitHub 分支保护或 rulesets，无法在服务端硬性阻止直推。首次克隆后运行 `bash script/setup-git-hooks.sh` 启用 `.githooks/pre-push`，在本地阻止直接推送 `main`；CI 和本地 hook 共同兜底。

### 15.3 本地手工验收

建议每次改动后按以下流程验收：

1. `bash script/dev.sh` 启动前后端；
2. 打开首页、文章列表、文章详情、标签、归档、关于；
3. 检查移动端宽度、深浅色切换、键盘 Tab 导航；
4. 进入 `/admin`，确认统计数字和最近编辑；
5. 新建文章，输入标题、slug、摘要、标签和 Markdown；
6. 确认实时预览与公开页使用同一后端渲染结果；
7. 保存草稿，刷新后确认内容仍在；
8. 发布文章，打开公开详情页；
9. 上传图片，复制 `/images/...` 地址并确认可访问；
10. 归档文章，确认公开页面不再展示；
11. 检查 `log/backend/YYYY-MM-DD.log` 与 `log/frontend/YYYY-MM-DD.log` 有对应请求记录；
12. 检查 RSS、Sitemap 和 404 页面。

### 15.4 生产阶段补充

进入 Cloudflare 阶段后需要补充：

- slug、标题、正文、分页边界的参数化测试；
- 未认证管理请求必须被拒绝；
- 图片类型、大小、重复上传和引用删除；
- D1 / R2 失败时返回统一错误，不产生不完整数据；
- Miniflare 加载 worker-build 产物做 HTTP 端到端测试；
- 文章页 CPU 预算压测（5,000 中文字、10 个标签、10 张图片），记录 p50/p95，目标 p95 低于 8 ms；
- 上线验收：草稿 → 上传 → 发布 → 公开页 → 修改 → 撤回 → 备份可读。
