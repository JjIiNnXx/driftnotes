# 测试方案

> 文档集索引：[index.toml](../index.toml) · 来源：飞书《个人博客技术方案》v1.1（2026-10-28），已按当前本地实现更新

## 15. 测试方案

### 15.1 当前自动化检查

本地唯一质量门禁是：

```bash
bash script/check.sh
# 或 npm run check
```

执行顺序：

1. 校验 `docs/index.toml` 可解析，且索引中的文档路径都存在；
2. `cargo fmt --check`；
3. `cargo clippy --all-targets -- -D warnings`；
4. `cargo test`；
5. `astro check`（`.astro`、`.ts` 类型检查）；
6. `astro build`。

当前 Rust 单元测试覆盖纯逻辑：

- 图片 Magic Bytes 识别；
- Markdown 代码块渲染；
- 原始 HTML 与危险链接净化；
- 日志日期解析与 3 天保留边界。

本地没有前端单元测试；`astro check` 负责类型检查，`astro build` 负责构建门禁，CI 运行同一套检查。

### 15.2 CI 与分支保护

CI 只有一个工作流 `.github/workflows/ci.yml`，只在 pull request 打开、更新、重新打开或转为 ready 时运行。PR 事件下 GitHub Actions 默认检出 `refs/pull/<n>/merge`，因此检查的是“把该 PR 合入 `main` 后”的结果，而不是只检查分支本身。

任务 `ci` 依次执行：

1. 固定版本 gitleaks（下载后校验 SHA-256）扫描完整提交历史，日志中的密钥会被脱敏；
2. 拒绝被 Git 跟踪的 `.env*` 文件（`.env.example` 除外）；
3. `npm ci`；
4. `bash script/check.sh`，即上节的 6 项本地检查。

任何一步失败，`ci` 检查即变红。

`main` 已开启 GitHub 分支保护，规则对管理员同样生效：

- 必须通过 PR 合入，禁止直接推送、force push 和删除分支；
- 必需检查为 `ci`，为红时合并按钮不可用；
- 要求分支与 `main` 同步（strict），历史保持线性；
- 只允许 rebase merge，合并后自动删除 head 分支。

仓库同时开启 GitHub 自带的 secret scanning 与 push protection，推送含已知密钥的提交会被服务端直接拒绝。

PR 只能由维护者在 GitHub 网页手动点击 **Rebase and merge** 合入。Agent 不得执行 `gh pr merge`、调用合并 API、开启 auto-merge 或直接推送 `main`；仓库已关闭 auto-merge。

本地 `.githooks/pre-push` 仍会在推送前拦截直推 `main`，避免推到远端才被拒绝；首次克隆后运行 `bash script/setup-git-hooks.sh` 启用。

### 15.3 本地手工验收

建议每次改动后按以下流程验收：

1. `bash script/dev.sh` 启动前后端；
2. 打开首页、文章列表、文章详情、标签、归档、关于；
3. 检查移动端宽度、深浅色切换、键盘 Tab 导航；
4. 进入 `/admin`，确认统计数字和最近编辑；
5. 新建文章，输入标题、slug、摘要、标签和 Markdown；
6. 确认实时预览与公开页使用同一后端渲染结果；
7. 保存草稿，刷新后确认内容仍在；
8. 发布文章，打开公开详情页；
9. 上传图片，复制 `/images/...` 地址并确认可访问；
10. 归档文章，确认公开页面不再展示；
11. 检查 `log/backend/YYYY-MM-DD.log` 与 `log/frontend/YYYY-MM-DD.log` 有对应请求记录；
12. 检查 RSS、Sitemap 和 404 页面。

### 15.4 生产阶段补充

进入 Cloudflare 阶段后需要补充：

- slug、标题、正文、分页边界的参数化测试；
- 未认证管理请求必须被拒绝；
- 图片类型、大小、重复上传和引用删除；
- D1 / R2 失败时返回统一错误，不产生不完整数据；
- Miniflare 加载 worker-build 产物做 HTTP 端到端测试；
- 文章页 CPU 预算压测（5,000 中文字、10 个标签、10 张图片），记录 p50/p95，目标 p95 低于 8 ms；
- 上线验收：草稿 → 上传 → 发布 → 公开页 → 修改 → 撤回 → 备份可读。
