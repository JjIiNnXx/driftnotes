## 9. 认证与安全设计

> 本地 MVP 状态：管理接口**没有认证**，仅允许在 `127.0.0.1` 使用，不能直接暴露到公网。下面描述的是生产阶段必须补齐的方案。

### 9.1 管理入口保护

优先使用 Cloudflare Access 保护 `/admin/*` 与 `/api/admin/*`。截至 2026 年，Access 支持对 `workers.dev` 主机名做 path-based 保护，不需要先买域名；需在 Zero Trust 中启用 Access、配置身份源（邮箱 OTP 即可），并用 Application paths 同时覆盖页面和接口。

**关键限制：**Astro 使用 Workers Static Assets 时，请求会经过内部 router，`ctx.access` 不会传给用户 Worker。因此要在 Astro 中间件校验 `Cf-Access-Jwt-Assertion`（缓存 JWKS，校验 audience/issuer），或至少由 Web Worker 附加内部 HMAC 头并由 Rust API 校验；不能只凭“路径被 Access 保护”就信任请求。Access 登录过期时 API fetch 会收到 302/HTML，前端需检测并整页跳转重新登录。若不用 Access，自实现登录必须评估 Wasm 密码哈希 CPU，建议 GitHub OAuth + 签名 Cookie 替代密码。若后续启用 Workers Cache，`/admin/*` 与 `/api/admin/*` 必须显式返回 `Cache-Control: no-store`；不要依赖 Access Cookie 自动绕过缓存。

### 9.2 基础安全要求

- 管理接口必须同时在 Worker 内校验身份，不只依赖前端隐藏入口；Markdown 禁止原始 HTML，过滤 `javascript:` 等危险链接，并在发布时净化 `content_html`。
- 所有 SQL 使用参数绑定，禁止字符串拼接 SQL。
- 后台变更请求校验 Origin，并加入 CSRF 防护。
- 认证 Cookie 使用 `HttpOnly`、`Secure` 和适当的 `SameSite`。
- 管理响应使用 `Cache-Control: no-store`。
- 上传接口限制文件大小、类型和频率，检查文件头与像素尺寸，防止伪造 MIME 和解压炸弹；敏感接口使用 Rate Limiting binding 或 D1 计数限流。
- 不根据扩展名判断图片类型，应检查文件头。
- SVG、HTML 等可能携带主动内容的文件不作为普通图片公开上传。
- 密钥只使用 Workers Secrets，不写入 Git。
- 仓库禁止提交 `.env*`、私钥和令牌。`ci` 检查用 gitleaks 扫描完整历史，GitHub 的 secret scanning 与 push protection 也会拒绝已知密钥；误提交后必须吊销密钥，不能只删除文件。
- 后台错误不向前端泄露数据库连接信息和内部堆栈。
- 删除文章默认先归档，物理删除作为单独操作。
- 图片可能包含 EXIF/GPS 信息，发布前提示作者清理；第一版不做服务端重编码。

### 9.3 建议安全响应头

```Plaintext
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: 按实际资源来源配置
Permissions-Policy: 禁用不需要的浏览器能力
```
