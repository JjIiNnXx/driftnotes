# 本地实现说明

> 文档集索引：[index.toml](../index.toml) · 当前本地 MVP 的实现现状

## 运行形态

本地 MVP 不依赖任何付费服务，进程只有两个：

```text
浏览器
  ├── Astro SSR :4321 ── HTTP ──> Rust API :8787
  │                                  ├── SQLite  backend/data/blog.db
  │                                  └── 本地文件 backend/data/storage
  └── /api、/images 由 Vite 代理到 Rust API
```

Astro 在服务端渲染页面时直接请求 Rust API；管理后台的浏览器端预览、保存和上传请求走同源 `/api`，由 Astro dev server 代理。

## 后端分层

```text
handlers/         HTTP 参数、状态码、JSON 响应
services/         业务规则：发布、版本冲突、slug、标签、Markdown、上传
repositories/     SQLite 查询与事务
storage/          对象存储抽象（本地目录）
db/               建表、迁移入口、示例数据
models.rs         请求/响应数据结构
router.rs         路由与中间件
```

约束：

- D1/R2 访问只发生在 Rust 后端，前端不直连数据库。
- 正文同时保存 `content_markdown` 与发布时生成的 `content_html`。
- 公开文章只返回 `status = published`。
- 更新使用 `version` 乐观锁；发布后不允许修改 slug。
- 标签按名称或 slug 解析，未知标签在保存时自动创建。
- 图片只接受真实 Magic Bytes 匹配的 JPEG/PNG/GIF/WebP，使用 SHA-256 去重。

## API 契约

统一前缀 `/api`，成功响应为 `{ "data": ... }`，失败为：

```json
{ "error": { "code": "BAD_REQUEST", "message": "..." } }
```

分页字段使用 snake_case：

```json
{
  "data": {
    "items": [],
    "pagination": {
      "page": 1,
      "page_size": 10,
      "total": 8,
      "total_pages": 1
    }
  }
}
```

主要接口：

| 方法 | 路径 | 说明 |
|-|-|-|
| GET | `/api/posts?page=1&page_size=10&tag=&q=` | 已发布文章 |
| GET | `/api/posts/:slug` | 文章详情 + 上一篇/下一篇 |
| GET | `/api/tags` | 标签与已发布文章数 |
| GET | `/api/archive` | 按年/月分组的归档 |
| GET | `/api/admin/stats` | 后台统计 |
| GET/POST | `/api/admin/posts` | 后台列表 / 新建 |
| GET/PUT/DELETE | `/api/admin/posts/:id` | 详情 / 更新 / 归档 |
| POST | `/api/admin/render` | Markdown 预览 |
| GET/POST | `/api/admin/assets` | 图片列表 / 上传 |
| DELETE | `/api/admin/assets/:id` | 删除未被引用的图片 |
| GET | `/images/*` | 本地对象存储读取 |

## 本地到生产的映射

| 本地 | 生产目标 |
|-|-|
| Rust + Axum | Rust → WebAssembly，运行于 Cloudflare Workers |
| `rusqlite` + `blog.db` | Cloudflare D1 |
| `backend/data/storage` | Cloudflare R2 |
| Astro dev server | Astro + `@astrojs/cloudflare` |
| 无认证 | Cloudflare Access + 服务端身份校验 |
| Vite `/api` 代理 | Worker 路由 / Service Binding |

本地 SQLite 表结构有意贴近 D1：`posts`、`tags`、`post_tags`、`assets`、`settings`。迁移到 D1 时主要替换 repository 的数据库调用和 storage 实现，业务层与 HTTP 契约保持不变。

## 本地日志

- 后端：`log/backend/YYYY-MM-DD.log`，由 `backend/src/logging.rs` 记录启动、SQLite 初始化、HTTP 请求、文章/图片操作和内部错误。
- 前端：`log/frontend/YYYY-MM-DD.log`，由 `frontend/plugins/request-logger.mjs` 记录 SSR 页面、`/api`、`/images` 和 XML 请求。
- 每天一个文件，保留 3 天，启动时清理一次，之后每 72 小时清理一次。
- 日志不记录请求体、Markdown 正文、Cookie、Authorization 或密钥。
- 详细格式与查看方式见 [日志规范](04-日志规范.md)。

## 本地限制

- 管理接口无认证，不能直接暴露到公网。
- 没有评论、全文搜索、图片裁剪和多作者权限。
- 图片按原始字节存储，不生成响应式尺寸。
- Markdown 渲染在主线程完成，适合个人博客规模；生产需按方案做 CPU 预算与压测。
